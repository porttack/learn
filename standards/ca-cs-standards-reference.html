What this is. A locally built index of California's 9-12 Computer Science core standards (adopted 2018), for linking from standards-alignment work. What this is not. Original paraphrases, not the CDE's text; only codes are reproduced as-is.

#AP Algorithms & Programming

#6-8.AP.10

Flowcharts and pseudocode let you design and check an algorithm before writing any real code.

Unassigned

#6-8.AP.11

A variable's name should say what it holds, since that's what makes the operations performed on it make sense to someone reading the code.

Covered by CMU Exploring Programming with Python: Unit 1 (Drawing with Shapes)

Drawing with Shapes, an introductory graphics unit, is where a first course names variables for shape properties (position, size, color) -- inferred from the unit title alone, not a confirmed lesson breakdown.

#6-8.AP.12

Real programs combine multiple control structures and compound conditions, and get built up iteratively rather than all at once.

Covered by CMU Exploring Programming with Python: Unit 2 (Basic Animations), Unit 3 (Giving Programs Options), Unit 4 (Animating Lots of Shapes)

Basic Animations (a repeating step mechanism), Giving Programs Options (the unit's own title names branching), and Animating Lots of Shapes (looping over many objects) are each control-structure content, built up across three units rather than introduced all at once. Inferred from unit titles.

#6-8.AP.13

Breaking a problem into smaller subproblems makes it possible to design, build, and review a program piece by piece.

Covered by CMU Exploring Programming with Python: Unit 4.1 (Unit 4, Lesson 1 (within Animating Lots of Shapes))

Per the teacher's own knowledge of this lesson (not documented in CMU's own published materials): Unit 4's first lesson has students break the many-shapes problem into smaller subproblems before assembling the full animation.

#6-8.AP.14

A procedure that takes parameters can be reused for many different inputs instead of being rewritten each time.

Unassigned

#6-8.AP.15

A solution actually meets user needs only if you go get feedback from teammates and users and use it to refine the design.

Covered by CMU Exploring Programming with Python: Unit creative-task (Creative Tasks (every unit, 1-4))

CMU's Creative Task feature (shared across its courses, including CS1) asks for a design intent statement, but its rubric doesn't itself require a feedback step -- whether this standard is actually met depends on the teacher building one in, same caveat cmu_cs1.json carries for the 9-12 equivalent (AP.18).

#6-8.AP.16

Reusing someone else's code, media, or library in your own program is normal practice, as long as you credit where it came from.

Unassigned

#6-8.AP.17

Testing a program well means trying a deliberate range of test cases, not just the one you expect to work.

Unassigned

#6-8.AP.18

Building something as a team means splitting up tasks and keeping to a shared timeline, not just dividing the code.

Covered by CMU Exploring Programming with Python: Unit collaborative (Collaborative tasks)

A stretch, by the teacher's own admission: CS0's collaborative tasks split work between partners, which is this standard's own team/role framing, though it's a lighter, shorter-form version of it than a full-length course's collaborative work would be.

#6-8.AP.19

#9-12.AP.12

Solving a computational problem often means combining an algorithm you already know with one you design yourself.

Covered by CMU Exploring Programming with Python, no locator on record; Covered by CMU CS Academy — CS1: Unit 8 (Math Functions, Random, Nested Loops), Unit 11 (2D Lists and Board Games); Covered by CodeHS — Corgi (Intro to JS): Unit 2 (Karel Challenges), Unit 5 (Graphics Challenges), Unit 7 (Control Structures Challenges), Unit 9 (Functions Challenges), Unit 11 (Animations Challenges); Covered by CS50 AP -- taught subset (weeks 0, 3, 4, 7-9): Unit 3 (Week 3: Algorithms (searching, sorting, asymptotic notation, recursion)); Covered by Working in Python: Chapter 7 (Iteration and Search), Chapter 9 (Lists)

CMU's own CA alignment doc, Subconcept Algorithms: 'Design algorithms to solve computational problems using a combination of original and existing algorithms.' Concept-level claim, not lesson-localized in that document.

Math/random/nested loops (unit 8) and 2D lists/board-game logic (unit 11) both involve choosing and adapting existing algorithms.

Recurs across every 'challenges' unit (2, 5, 7, 9, 11) -- larger problems that call for choosing among algorithms already introduced.

Same algorithms-comparison claim as apcsp 3.9.

Chapter 7 develops a linear-search algorithm from scratch; Chapter 9's 'Sorting lists' uses an existing (built-in) sort. Together they match 'combination of original and existing algorithms' well.

#9-12.AP.13

Once a problem needs more than a handful of related values, a collection replaces a pile of separately named variables.

Covered by CMU Exploring Programming with Python, no locator on record; Covered by CMU CS Academy — CS1: Unit 10 (Lists and Return Values), Unit 11 (2D Lists and Board Games); Covered by CodeHS — Corgi (Intro to JS): Unit optional-extension (Optional extension: Data Structures); Covered by CS50 AP -- extended (weeks 0-6 remainder): Unit 2 (Week 2: Arrays), Unit 5 (Week 5: Data Structures); Covered by CS50 Python -- weeks 0-8: Unit 2 (Lecture 2: Loops, Lists, Dictionaries); Covered by Working in Python: Chapter 9 (Lists)

CMU's own CA alignment doc, Subconcept Variables: 'Create more generalized computational solutions using collections instead of repeatedly using simple variables.'

Lists and 2D lists are core, assessed content (units 10-11), not an optional add-on.

Arrays, lists, objects, sets, and grids live only in an optional extension sequenced after the final project -- the final exam's own listed coverage never touches them. Whether a student ever meets this standard depends on whether their teacher assigns material after the course is functionally over. Included because the extension exists, not because it's reliably taught.

Arrays (week 2) and the named Abstract Data Types (week 5) are collections replacing separately named variables.

Lists and Dictionaries, named week-2 headings, are the collection this standard describes.

Direct match to Chapter 9 (Lists).

#9-12.AP.14

Different control structures for the same task read differently and run differently, and choosing between them is a real design decision.

Covered by CMU CS Academy — CS1: Unit 3 (Mouse Motion, Conditionals, Helper Functions), Unit 4 (More Conditionals, Key Events, Methods), Unit 5 (Complex Conditionals, More Key Events), Unit 7 (New Shapes, Local Variables, For Loops), Unit 8 (Math Functions, Random, Nested Loops), Unit 9 (Types, Strings, While Loops), Unit creative-task (Creative Task (every unit, 1-10)); Covered by CodeHS — Corgi (Intro to JS): Unit 1 (Programming with Karel), Unit 6 (JavaScript Control Structures), Unit 7 (Control Structures Challenges); Covered by CS50 AP -- extended (weeks 0-6 remainder): Unit 1 (Week 1: C), Unit 6 (Week 6: Python); Covered by CS50 Python -- weeks 0-8: Unit 1 (Lecture 1: Conditionals); Covered by Working in Python: Chapter 5 (Conditionals and Recursion), Chapter 6 (Return Values)

Woven through every conditionals/loop unit (3-5, 7-9) and made explicit in the Creative Task's own design step, which has students list the concepts they plan to use and justify why -- the standard's own language, 'justify the selection.' Not in CMU's own official standards document; the teacher's own classroom analysis argues it should be.

Control-structure choice appears in Karel (unit 1) and the JavaScript control-structures units (6-7), though this is inferred from the syllabus's topic list, not audited against the platform directly.

The same Conditionals/Loops task reads and runs differently in C versus Python -- a real, named-topic-grounded control-structure choice.

if/elif/else and match are two different, named control structures for the same branching task -- a real, explicit choice in the week's own material.

Strong match: the CED's own worked example here is comparing iterative vs. recursive Fibonacci -- and Chapter 6 has a 'Fibonacci' section built on Chapter 5's recursion material. The book only ever demonstrates the recursive side (see the AP index's 3.8 Iteration note on the missing `while` loop), so the iterative half of this comparison is thinner than the recursive half.

#9-12.AP.15

A program built around events -- a button press, a timer -- responds to things happening rather than running start to finish in one line.

Covered by CMU Exploring Programming with Python, no locator on record; Covered by CMU CS Academy — CS1: Unit 2 (Functions, Mouse Events, Properties), Unit 3 (Mouse Motion, Conditionals, Helper Functions), Unit 4 (More Conditionals, Key Events, Methods), Unit 5 (Complex Conditionals, More Key Events), Unit 6 (Groups, Step Events, Motion), Unit 12 (Final Project); Covered by CodeHS — Corgi (Intro to JS): Unit 10 (Animation and Games), Unit 11 (Animations Challenges), Unit 12 (Project: Breakout); Not covered by Working in Python

CMU's own CA alignment doc, Subconcept Control: 'Iteratively design and develop computational artifacts... by using events to initiate instructions.'

Iterative development through events (mouse, key, step) recurs across units 2-6 and the final project (unit 12).

Iterative development via animation/game events across units 10-12.

Real gap: every program in this book runs top-to-bottom to completion. There is no event-driven or GUI programming anywhere in chapters 1-13 (turtle graphics is imperative, not event-based).

#9-12.AP.16

Breaking a big problem into smaller ones, each solved by its own procedure, module, or class, is what makes a complex program manageable.

Covered by CMU CS Academy — CS1: Unit 3 (Mouse Motion, Conditionals, Helper Functions); Covered by CodeHS — Corgi (Intro to JS): Unit 1 (Programming with Karel), Unit 2 (Karel Challenges); Covered by CS50 AP -- extended (weeks 0-6 remainder): Unit 2 (Week 2: Arrays), Unit 6 (Week 6: Python); Covered by CS50 Python -- weeks 0-8: Unit 0 (Lecture 0: Functions, Variables, Strings, def), Unit 8 (Lecture 8: Object-Oriented Programming); Covered by Working in Python: Chapter 3 (Functions), Chapter 4 (Functions and Interfaces)

Helper functions, introduced in unit 3, are decomposition into subproblems.

Karel's top-down design (units 1-2) is decomposition into subproblems.

Functions (named in both weeks) are decomposition into a subproblem solved on its own.

Functions (week 0) and Classes (week 8) are both named ways of decomposing a program into its own procedure or class.

Chapter 3/Chapter 4's function-decomposition material carries the procedure half directly. Chapters 14-19 (classes) carry the class-based half of this standard too, but that range is independent-study/post-AP pathway per the treatment matrix, not part of the Aug-Dec sequence this standard would be taught alongside.
