AP Computer Science Principles

#2.3 Extracting Information from Data AP Computer Science Principles

Raw data becomes information once a program finds the patterns in it, and real data sets are rarely clean enough to do that without some processing first.

Covered in Unit 2 (Introducing the Dataset: Animal-Vehicle Collisions in Vermont — Notice and Wonder), Unit 4 (Scatter Plots, Outliers & Human Error), Unit 5 (More Pie Charts & Bar Charts), Unit 6 (Comparing Subsets / Making Predictions Using Proportional Reasoning), Unit 9 (Data-Informed Decision Making)

Part 2's Notice-and-Wonder on the raw Vermont spreadsheet, Part 4's outlier/human-error reasoning, Part 5's real breakdown (Deer 436, Bird 82, Fox 71, Coyote 67, Beaver 59, Moose 32, Bear 14, Turtle 10, Bobcat 6, Squirrel 4), Part 6's cross-highway comparison, and Part 9's final recommendation all turn a messy real dataset into actual information.

#2.4 Using Programs with Data AP Computer Science Principles

Programs that read, combine, and rewrite data files let a person do with a data set what would be impractical by hand.

Covered in Unit 6 (Comparing Subsets / Making Predictions Using Proportional Reasoning), Unit 7 (Patterns in the Code — More Subsets & Pie Charts via Filtering)

Part 6 and Part 7 both build new tables from the base dataset via `.filter()` (by route/highway, then by animal type) -- using a program to do with the data what would be impractical by hand.

#3.12 Calling Procedures AP Computer Science Principles

Calling a function hands control to a separate block of code and, often, gets a value back in return.

Covered in Unit 7 (Patterns in the Code — More Subsets & Pie Charts via Filtering)

Coding Challenge only. Students pass their own `is-deer` function into `collisions-table.filter(is-deer)` -- calling a procedure they just wrote and getting a table back.

#3.13 Developing Procedures AP Computer Science Principles

Writing a function well means giving it parameters general enough to be reused, and a name and docstring that explain what it does without exposing how.

Covered in Unit 7 (Patterns in the Code — More Subsets & Pie Charts via Filtering), Unit 8 (Analyzing Scatter Plots Using Rate of Change)

Coding Challenge only. `is-deer` and `year-dot` are both student-written functions with a parameter (`r`) general enough to be reused across rows, matching the pattern of the pre-written functions around them.

#3.2 Data Abstraction AP Computer Science Principles

Grouping related values under one name lets a program treat a collection as a single thing instead of tracking each part separately.

Covered in Unit 3 (Introducing the Pyret Programming Environment — Bar Chart / Pie Chart), Unit 6 (Comparing Subsets / Making Predictions Using Proportional Reasoning), Unit 7 (Patterns in the Code — More Subsets & Pie Charts via Filtering)

The whole activity runs on one `collisions-table` (a Pyret table), queried throughout by row access (`r["animals"]`, `r["year"]`, `r["route"]`) and `.filter()` -- grouping each collision record's related values under one name and treating the collection as a single thing.

#3.6 Conditionals AP Computer Science Principles

An if-statement lets a program take one path or another depending on whether a condition holds.

Covered in Unit 8 (Analyzing Scatter Plots Using Rate of Change)

Coding Challenge only. Part 8's optional challenge has students write `year-dot`, an if/else-if function choosing a point's shape/color by year (`if r["year"] == 2004: ... else if r["year"] == 2005: ... end`). Only reached by students who attempt the star-challenge track.

#3.9 Developing Algorithms AP Computer Science Principles

Building an algorithm from scratch usually means starting with a rough version and refining it in small, testable steps.

Covered in Unit 7 (Patterns in the Code — More Subsets & Pie Charts via Filtering)

Coding Challenge only. Part 7 has students write a predicate function (`is-deer`) from scratch, following the pattern of ones already shown, then plug it into `.filter()` -- incremental algorithm development, not just running provided code.

California Computer Science Standards

#6-8.DA.7 California 6-8 Computer Science

The same data can be represented in more than one way, and choosing a representation changes what's easy to see in it.

Covered in Unit 3 (Introducing the Pyret Programming Environment — Bar Chart / Pie Chart), Unit 5 (More Pie Charts & Bar Charts), Unit 6 (Comparing Subsets / Making Predictions Using Proportional Reasoning), Unit 7 (Patterns in the Code — More Subsets & Pie Charts via Filtering), Unit 8 (Analyzing Scatter Plots Using Rate of Change)

Same representation-choice argument as 9-12.DA.10 above, at the MS band -- same parts of the activity, since it's one lesson used at both levels with different scaffolding (Bootstrap's own note: MS needs guidance, HS can work independently).

#6-8.DA.8 California 6-8 Computer Science

Raw data collected with computational tools usually needs to be transformed before it's actually useful for answering a question.

Covered in Unit 2 (Introducing the Dataset: Animal-Vehicle Collisions in Vermont — Notice and Wonder), Unit 4 (Scatter Plots, Outliers & Human Error), Unit 7 (Patterns in the Code — More Subsets & Pie Charts via Filtering)

Notice-and-Wonder (Part 2), the outlier/human-error catch (Part 4), and filtering by route or animal (Part 7) are all raw data being transformed before it's useful -- this standard's own scope.

#6-8.DA.9 California 6-8 Computer Science

A computational model lets you change one variable at a time and observe the effect, which is how you test what's actually driving a result.

Covered in Unit 6 (Comparing Subsets / Making Predictions Using Proportional Reasoning), Unit 8 (Analyzing Scatter Plots Using Rate of Change)

Part 6 compares raccoon-collision rates between I-89 and I-91 (changing which subset, observing the effect), and Part 8 compares 2004 vs 2005 collision rates by slope -- both change one variable and observe the effect on the same dataset.

#9-12.DA.10 California 9-12 Computer Science

Turning a data set into a visualization is itself a design choice that shapes what other people take away from it.

Covered in Unit 3 (Introducing the Pyret Programming Environment — Bar Chart / Pie Chart), Unit 5 (More Pie Charts & Bar Charts), Unit 6 (Comparing Subsets / Making Predictions Using Proportional Reasoning), Unit 7 (Patterns in the Code — More Subsets & Pie Charts via Filtering), Unit 8 (Analyzing Scatter Plots Using Rate of Change)

Parts 3/5/7 move through bar, pie, and filtered-subset charts of the same dataset. Part 6's Teacher Moves note is the standard almost verbatim as a real gotcha, not just theory: 'a blue wedge does not necessarily represent the same animal in both charts' -- students are explicitly warned that the same visualization choice can mislead across two pie charts built from different subsets.

#9-12.DA.11 California 9-12 Computer Science

A computational model is only useful once it's been checked against real observations and adjusted where it doesn't match.

Covered in Unit 4 (Scatter Plots, Outliers & Human Error)

Part 4's exact reasoning (screen 11 of the Teacher Guide) checks a model against real observations and catches the mismatch: 'both days and collisions are recorded in order from the start of the data collection period. If the deer hit on day 371 is collision number 657, it doesn't make sense that a deer hit 4 days earlier would be collision number 901' -- validating an assumption about the dataset's structure against what the data actually shows, and using the contradiction to identify a human-error outlier.
